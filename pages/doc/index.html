X_eTaL documentation

Files

  • library lib/Combinators.xtl: Combinators: the birds Raymond Smullyan names in "To Mock a Mockingbird" that type-check (a standard library, built into xetal). Import it with an alias of your choice: "c:" u_se< "Combinators". docs/birds.md lists them all; the self-applying birds (L, M, M2, U) have no finite type and are in demos/birds-untyped.xtl.
  • library lib/Geometry3D.xtl: Geometry3D: points in space as arrays (a standard library, built into xetal). Import it with an alias of your choice: "g:" u_se< "Geometry3D". Points are a 3-row matrix, x over y over z, one column per point, as []P_ATH takes 2 rows; a rotation is a 3 x 3 matrix, and turning the points is one inner product. A face is a 3 x 4 matrix of corners, and a solid is faces stacked along a new first axis (F x 3 x 4), so one expression orders them far to near for painting. Names with l: are exported; names with h: are private to this file.
  • library lib/Maybe.xtl: Maybe: a value that may be missing, and the monad that chains computations which can fail (a standard library, built into xetal). Import it with an alias of your choice: "m:" u_se< "Maybe".
  • library lib/Stats.xtl: Stats: a small statistics library (a standard library, built into xetal). Import it with an alias of your choice: "s:" u_se< "Stats". It is a demo library, loaded only by that import: a small subset of X_eTaL-libraries' Statistics, which has much more (a program may use either). Names with l: are exported; names with h: are private to this file.
  • library lib/Svg.xtl: Svg: pictures as SVG text, written for you (a standard library, built into xetal). Import it with an alias of your choice: "v:" u_se< "Svg". An element is its SVG text; a picture is elements joined with c_at inside v:p_icture, which []S_HOW shows and the command line writes. Points are a 2-row matrix, x over y, as []P_ATH and Geometry3D's g:p_roject give them; y grows downward, as SVG's does. Attributes are text made by v:a_ttr, v:f_ill, v:s_troke and the transforms, so no program writes a quote mark or an angle bracket of its own. Names with l: are exported; names with h: are private to this file.
  • library lib/Terminal.xtl: Terminal: the names of the colors and keys a program draws and reads with, a standard library built into xetal. Import it with an alias of your choice: "t:" u_se< "Terminal".
  • library lib/TTTML.xtl: TTTML: a machine that learns tic-tac-toe by playing itself (a standard library, built into xetal), ported from the TTTML workspace of sw-apl's library 1. Import it with an alias of your choice: "t:" u_se< "TTTML". docs/literate/tttml.org explains it; the demos demos/tttml.xtl, demos/tttml-train.xtl and demos/tttml-play.xtl use it.
  • library lib/Turtle.xtl: Turtle: turtle graphics as arrays (a standard library, built into xetal). Import it with an alias of your choice: "t:" u_se< "Turtle". A walk is a vector of turns in degrees, one before each step forward; the turtle starts at the origin facing east (0 degrees, counting anticlockwise). No turtle moves: the headings are a running sum of the turns, the steps are their cosines and sines, and the positions are running sums of the steps. Draw the points with []P_ATH. Names with l: are exported; names with h: are private to this file.
  • macro library lib/Combinators.xtlm: Combinators as macros: the birds of the Combinators library written in at compile time instead of applied when the program runs. Import both under one alias: "c:" u_se< "Combinators" finds Combinators.xtl (c:Y_, c:B_, ...) and this file (c:Y_<, c:B_<).
  • macro library lib/Macros.xtlm: A small macro library, an example of macros of your own (MC10). A macro is an ordinary function of the source text written on each side of its call; the text it gives replaces the call, then is read as code. Import it with an alias of your own, "x:" u_se< "Macros", and see what a program becomes with xetal expand FILE.
  • system macros std/System.xtlm: The system macros (lang-choices MC18, MC19, MC24), loaded before every file with no import and no alias: each is called unprefixed, as "c" i_f< "a; b". A macro is a function of the source text on each side of its call; the text it gives replaces the call. @ on a side means the macro takes nothing there (MC22). What only the compiler knows comes from hooks (MC20), usable only in a macro body.
  • program demos/arrays.xtl: Arrays: dense arrays, 1-origin indexing, the structural built-ins and scalar extension. Run it with "xetal run demos/arrays.xtl" (or "./demos/arrays.xtl"); it prints the result of each line after the definition of m: the matrix, its shape, a row, the last row, the matrix times ten, a row joined to more items and powers of ten. Read it for how r_eshape, s_elect, t_ake and c_at treat a matrix.
  • program demos/combinators.xtl: Combinators: the Combinators library, Smullyan's birds, each a function that only rearranges, repeats or drops its arguments. Run it with "xetal run demos/combinators.xtl" (or "./demos/combinators.xtl"), or as a notebook with "just show demos/combinators.xtl"; it prints what each bird makes of small numbers, ending with 10 factorial from Y and 1024 from a function power. docs/birds.md lists every bird.
  • program demos/factorial.xtl: Factorial: recursion with guards, one statement per line. Run it with "xetal run demos/factorial.xtl" (or "./demos/factorial.xtl"); it prints 3628800, the factorial of 10. Read u:f_act for how a guard (`c ? r`) ends a function early and how a function calls itself.
  • program demos/hello-library.xtl: Hello library: a program using two libraries of its own, userlibs/Hello.xtl and userlibs/Greetings.xtl. Run it from the repository's root with "xetal run demos/hello-library.xtl" (or "./demos/hello-library.xtl"); it prints a greeting and two personal greetings. Read the imports for how u_se< finds a library: "Hello" is Hello.xtl beside this file, then in userlibs/, then on XETAL_PATH, then among the standard libraries; the string on its left is the prefix the library's l: names get here.
  • library userlibs/Hello.xtl: Hello: the smallest library, one greeting. A library is an ordinary file whose exported names start with l:; libraries of your own live in userlibs/, on the search path. demos/hello-library.xtl imports it ("hi:" u_se< "Hello"), and docs/literate/hello.org walks through both. The name in the string is the logo: typed X_ e:T a:L, drawn, spaces removed (a string may hold any Unicode).
  • library userlibs/Greetings.xtl: Greetings: a library with a private name. h:n_ame is file-private, so it is used here but cannot be imported; g_reet is exported, and takes the greeting from the program that calls it. Import it with an alias of your choice: "g:" u_se< "Greetings" (it is found in userlibs/).
  • program demos/higher-order.xtl: Higher-order built-ins: they take quoted functions as operands, as `'+ r_/ v` reduces v with plus. Run it with "xetal run demos/higher-order.xtl" (or "./demos/higher-order.xtl"); it prints the result of each line: reductions, a scan, an outer and an inner product, e_ach, c_ompose and s_wap, then the search and order built-ins s_ort, g_rade, u_nique, i_ndexOf and w_here.
  • program demos/keys.xtl: Keys: every way X_eTaL is typed. Each line of code appears twice: drawn decorated, as "just pp demos/keys.xtl" shows it, and at the end of the line, after "typed:", exactly the keys you type (a comment is drawn as written, so that text stays plain ASCII). Run it with "xetal run demos/keys.xtl" (or "./demos/keys.xtl") to print each line's result, or "just show demos/keys.xtl" to see each line next to its result. docs/input.md explains each form.
  • program demos/life.xtl: Life: Conway's Game of Life in one line, u:l_ife, then a blinker and a glider run through it. Run it with "xetal run demos/life.xtl" (or "./demos/life.xtl"); it prints a blinker after one and two steps, 1s showing that two steps restore it, then a glider's five generations a blank line apart. Read u:l_ife for reduce and rotate along both axes at once (the `_12` subscripts).
  • program demos/macros.xtl: Macros write source for you: a call "left" n_ame< "right" is replaced, before the program is checked, by the source the macro writes from the two texts. Run it with ./demos/macros.xtl (or xetal run): it prints what the system macros give, then a macro library's checks; a failed a_ssert< goes to standard error. Read each call beside its expansion, which "xetal expand demos/macros.xtl" shows.
  • program demos/magmas.xtl: Magmas: a set with a binary operation that stays in the set, and nothing more is promised. Rock-paper-scissors is one: x played against y gives the winner (x on a tie). With its table we can ask which laws hold, for every case at once.
  • program demos/monads.xtl: The Maybe monad from the Maybe library: computations that can fail, chained so that the first failure stops the chain.
  • program demos/rotate.xtl: Rotate along both axes: every frame moves the arrow one row down and one column right, wrapping around the edges of the board.
  • program demos/square.xtl: A user function with the shorthand right argument `_r`. Run it with ./demos/square.xtl or "xetal run demos/square.xtl"; it prints 49.
  • program demos/stats.xtl: Using a library: Stats is a standard library, built into xetal (lib/Stats.xtl). The alias "s:" is this file's name for it: its exported names are used as s:m_ean and so on.
  • program demos/sub.xtl: A dyadic user function; every function is curried. Run it with ./demos/sub.xtl or "xetal run demos/sub.xtl"; it prints 7 twice, from `10 u:s_ub 3` and from the partial application u:t_enMinus.
  • program demos/tour.xtl: A tour of X_eTaL: one commented file touching every implemented feature, a section per topic, from numbers to Life in one line.
  • program demos/tttml-play.xtl: TTTML, part 2: play the machine that demos/tttml-train.xtl trained (run that first), with "xetal run demos/tttml-play.xtl". You are X and move first: type a square, 1 to 9, numbered row by row. Something that is not an empty square is asked for again. Uses the TTTML library (lib/TTTML.xtl).
  • program demos/tttml-train.xtl: TTTML, part 1: learn tic-tac-toe by playing itself, then save what it learned to work/tttml.model, a text file of numbers (the codes of the positions it met, then their values). Run it with "xetal run demos/tttml-train.xtl"; part 2, demos/tttml-play.xtl, loads the model and plays you. Uses the TTTML library (lib/TTTML.xtl).
  • program demos/tttml.xtl: TTTML: a machine that learns tic-tac-toe by playing itself, from the TTTML library (lib/TTTML.xtl, ported from sw-apl's TTTML workspace; docs/literate/tttml.org explains it). Run it with "xetal run demos/tttml.xtl", or as a notebook with "just tttml" (the optimized build: training takes seconds).
  • program demos/unit.xtl: A niladic function takes Unit, written @; `u:a_nswer 42` is a type error. Run it with ./demos/unit.xtl or "xetal run demos/unit.xtl"; it prints 42.
  • program demos/user-macros.xtl: A macro library of your own: userlibs/Repeat.xtlm (in the live demo, Repeat.xtlm among your files). It is found as a library of your own is, and its macro r:t_imes< writes statements as many times as you ask, when the program is expanded: a loop unrolled before it runs.
  • macro library userlibs/Repeat.xtlm: A macro library of your own (userlibs/, found as libraries of your own are): statements written as many times as you ask, when the program is expanded, a loop unrolled at compile time. Import it with an alias of your choice, "r:" u_se< "Repeat", and see what a program becomes with xetal expand FILE.
  • library demos/rosetta/Comparison.xtl: Comparison: the Rosetta stone's state machine (docs/rosetta.md), a library beside the demo ("cm:" u_se< "Comparison"). The state is one 4 x 5 matrix of numbers. The first three rows are the axes (the idiom drum, the top ring, the bottom ring), four columns each: how many items the axis has, how many steps it has taken (an integer; the item facing is 1 + steps, wrapped, and this is the truth), its angle in degrees (90 per step; the presentation, easing toward 90 * steps) and whether it plays on its own. The fourth row is the pointer: the axis being dragged (0 none, 0.5 pressed and not yet moved, else the axis), where it last was (x, y), how far it has moved in all, and the last turn it gave in degrees (for a flick). The fifth row is the attract mode's clock: seconds since the last interaction, seconds since its last step, and its two counters (how far the bottom ring is through its sweep of the other languages, how far the drum is through its sweep of the idioms). Nothing is ever inferred from an angle except what to draw. Every function gives a new state; none has an effect. Events (RS1) come in as []E_VENT gives them; cm:u_pdate takes one.

  • library demos/rosetta/Stone.xtl: Stone: the Rosetta stone's geometry and faces (docs/rosetta.md), a library beside the demo ("st:" u_se< "Stone"). The stone is three carousels sharing one place: the whole stone rolling about the x axis through the idioms (roll it up or down for the previous or next idiom), and its two halves, closed boxes, each turning about the y axis through the languages, one for the top half of the facing idiom, one for the bottom. Each is a square prism, so the geometry never changes: the facing side shows the current item and the sides at right angles show its neighbors, found by index; the lid of the top half and the floor of the bottom name the idioms before and after. The halves turn independently, which is the impossible part: no solid turns like this, and none needs to. Points are Geometry3D's (3 rows), pictures Svg's.
