Hello, library
writing a library of your own, and using it

A library is an ordinary X_eTaL file. The names it exports start with l:; a program imports it with u_se< and chooses the prefix those names get. This document writes the smallest library there is, one greeting, and uses it. Every block below is run by xetal through ob-xetal, and its result recorded under it.

The library

demos/Hello.xtl, the whole file: 

⍝ Hello: the smallest library, one greeting. A library is an ordinary
⍝ file whose exported names start with l:; demos/hello-library.xtl
⍝ imports it, and docs/literate/hello.org walks through both.

ˡh̲ello ← { @ → "hello X_eTaL" }

⍝ typed:
⍝   l:h_ello := { @ -> "hello X_eTaL" }

h_ello is a function (its h is underlined); l: exports it. Its argument is @, Unit, the value that stands for nothing: { @ -> ... } is a function of no real argument. It gives a string, which in X_eTaL is a vector of characters. xetal type on the library file lists what it exports: 

$ xetal type demos/Hello.xtl
l:h_ello : Unit -> Char

The type of a string is Char: types say what the items are, not how many there are.

Using it

A program imports the library under a prefix of its choosing. "h:" makes the library's l:h_ello this program's h:h_ello: 

ʰ⁼u̲se< "Hello"
ʰh̲ello @

⍝ typed:
⍝   "h:" u_se< "Hello"
⍝   h:h_ello @
hello X_eTaL

The whole program is demos/hello-library.xtl; just run demos/hello-library.xtl prints the same greeting.

Where a library is found

"Hello" is looked for as Hello.xtl beside the importing file, then in each directory of XETAL_PATH (separated by :), then among the standard libraries built into xetal (Stats, Maybe, Combinators, TTTML). A path finds one file exactly: "h:" u_se< "lib/Hello.xtl". This document's blocks run with XETAL_PATH set to demos/.

In the live demo, the library is one of your files: open Hello.xtl, change the greeting, Save, and run the hello-library demo again.

Mistakes it catches

The prefix is required, so every name says where it comes from: 

u_se< "Hello"
error[missing-alias]: u_se< needs an alias on its left: "c:" u_se< "Library"

Only what the library exports can be used, and the error says what it does export: 

"h:" u_se< "Hello"
h:g_oodbye @
error[not-exported]: h:g_oodbye is not defined by that library; it defines h_ello

And the types are checked across the import: 

"h:" u_se< "Hello"
h:h_ello 42
error[type-mismatch]: expected Unit, found a number

A second greeting

A library can keep names to itself: a name without l: is private. demos/Greetings.xtl builds both its greetings from one private g_reeting: 

⍝ Greetings: a library with a private name. g_reeting has no l:, so it
⍝ is used here but cannot be imported; h_ello and g_reet are exported.
⍝ docs/literate/hello.org uses it after Hello.

g̲reeting ← { @ → "hello " }
ˡh̲ello ← { @ → (g̲reeting @) c̲at "X_eTaL" }
ˡg̲reet ← { n → (g̲reeting @) c̲at n }

⍝ typed:
⍝   g_reeting := { @ -> "hello " }
⍝   l:h_ello := { @ -> (g_reeting @) c_at "X_eTaL" }
⍝   l:g_reet := { n -> (g_reeting @) c_at n }

(The parentheses matter: X_eTaL reads right to left, so without them g_reeting @ c_at n would join @ and n first.) A program can use the exported names: 

ᵍ⁼u̲se< "Greetings"
ᵍh̲ello @
ᵍg̲reet "world"

⍝ typed:
⍝   "g:" u_se< "Greetings"
⍝   g:h_ello @
⍝   g:g_reet "world"
hello X_eTaL
hello world

but not the private one: g:g_reeting @ is an error, not-exported, listing h_ello and g_reet.
