# launch-docs lane: release docs for X_eTaL (Saga 26 steps, done remotely)

A lane (branch per PR, from the latest origin/main) whose saga lives in
lanes/launch-docs/.agentrail; run agentrail with `--saga lanes/launch-docs`.
Given to a remote agent by the user (2026-10-03) so the local agent can
stay in the evaluator; it takes over main's release-status-table,
release-asks-ledger and the beginner part of release-fresh-user, which
the local agent skips and closes as these PRs merge.

Read first: CLAUDE.md, docs/research3.txt (the release review), and
docs/plan.md's release saga (Saga 26).

Steps, in order:
1. status-table: docs/status.md, "what works today": every feature as
   works, partial or planned, generated by a script from the built-in
   catalog (components/base/crates/xetal-catalog/builtins.toml), the
   spec cases and the decisions marked "not yet implemented" in
   docs/lang-choices.md; a gate check that it is current; the README's
   Status points at it.
2. asks-ledger: docs/asks.md, every ask filed in the sibling repos'
   docs/xetal-asks.md (X_eTaL-demos, -ML, -games, -libraries,
   -extensions; cloned from github.com/softwarewrighter) with its state
   here: landed (with the commit), planned (with the saga or step), or
   declined (with the reason); a script runs each ask's repro against
   this build.
3. beginner-path: docs/literate/beginner.org, a 15-minute path for a
   newcomer (typing ASCII and seeing it drawn, arrays, functions and
   operands, an axis, a train, a library import, where to go next),
   every example executed by the literate check or a reg golden, linked
   from README and Help; a placeholder section for macros.

Rules: TDD where code is involved; the gate before every commit; README
ASCII-only; no em dashes. One branch and PR per step
(pr/launch-docs-<slug>, from the latest origin/main). Design register
numbers from D70 up. Nothing in components/ beyond what a gate check
needs; pages/ is not rebuilt here. One CHANGES.md entry per commit. Say
in the PR what the sandbox could not run, so the merger runs it.
