User report: in the live demo tttml-train shows no output while it runs (it looks hung); the CLI streams progress. Do not buffer output in the web UI: run programs in a Web Worker (a second wasm, its own crate in components/web, built by trunk as a worker) that posts each line of output, each picture ([]S_HOW) and each file written ([]N_PUT) as they happen; the page appends them as they arrive, shows Running... and a Stop button (terminate the worker), and saves written files to local storage. The worker gets a snapshot of the saved files (workers have no local storage) for []N_GET and library lookup. A program that reads the keyboard ([]R_EAD) runs on the page as now, the prompt showing the latest output. Test first: xetal-play streams output through a writer as lines are written (native test), the message encoding round-trips; check in headless Chrome that tttml-train's progress lines appear before it ends.
