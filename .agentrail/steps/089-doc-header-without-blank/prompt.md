Reported by X_eTaL-libraries (2026-10-08; 25 demo and 12 library files had to add a blank line): a file's header ## block is attached to whatever follows it (an import line, a definition, a ### heading) unless a blank line separates them, and is then silently lost. Decided rule (the user: the blank line must not be required): the first ## block at the top of a file (after a #! line) is the file's doc, with or without a blank line after it; every other ## block documents the definition directly below it; a ## block with nothing to document (above an import, an expression or a ###) is not dropped silently: xetal doc warns doc-unattached at it. Test-first: xetal-doc tests for each layout (header then import, header then definition, header then ###, header then blank) and a warning golden; record in lang-choices (S9/S10, the doc comment rules) and the register; rebuild the doc pages; tell X_eTaL-libraries through the asks ledger (landed) that the blank lines are no longer needed.
