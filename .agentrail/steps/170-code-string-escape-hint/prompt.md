X_eTaL-ML's ask M18: a code string `c"..."` reads the backslash of a function name such as `o_\` or `s_\` as an escape, so `c"(Q '+ '* i_nner o_\ K)"` is `error[bad-string]: unknown escape: use \" \\ \n or \t` at the backslash, and nothing says that the verbatim form `c#"..."#` takes it as written. Two small changes: the lexer's unknown-escape error (xetal-lex string.rs, `escaped`) adds a help line naming `c#"..."#` (or `r#"..."#` for a plain string) when the backslash follows an underscore, as a function name's does, or always, as a note; and the string lints (xetal-strings in components/lint: escapes-could-be-raw and the others) look at code strings too, so a code string with backslash names gets `warning[escapes-could-be-raw]` with the fix `c#"..."#`. Test-first: a spec case for the error text, a lint test and a reg-rs golden for the fix. Docs: docs/lint.md's catalog rows, the code-strings section where escapes are described.
