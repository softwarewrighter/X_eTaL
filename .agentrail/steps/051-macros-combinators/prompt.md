User idea (2026-10-03): a Combinators.xtlm macro library beside lib/Combinators.xtl (one alias for both, MC11: c:Y_ the function, c:Y_< the macro), showing combinators evaluated at compile time. Y_< ties the knot in the source: it rewrites the self parameter of the function it is given to the name being defined, giving ordinary named recursion (no lazy ~ parameter, no thunk per call, no unfolding of Y f) - faster and a clear way to think about Y; B_< (and others where the arguments are written at the call, e.g. C_, W_) inline into a lambda instead of curried runtime applications (trains already do this in the desugarer, D45). Limits to state: a macro sees strings, so renaming must be by whole names; combinators passed as values stay runtime functions. The fibonacci demo gains a fifth way with c:Y_<, its xetal expand output shown, and a timing against the fourth (c:Y_). Tests: expansions pinned by goldens, results equal to the runtime combinators, docs (birds.org, classics.md).
