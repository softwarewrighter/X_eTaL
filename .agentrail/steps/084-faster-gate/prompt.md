A faster gate (user request, 2026-10-03, after a 20+ minute gate on merging PRs #43-#46): scripts/gate.sh walks 22 component workspaces one at a time, each running clippy (a check build with lints, metadata only) and then cargo test (a full build with code generation), which cannot share artifacts, so a change to a low crate (xetal-lex) recompiles nearly everything twice. Make it faster without weakening it: (1) components whose dependencies are all built run in parallel (base and syntax first, then the independent ones together, output kept per component and printed in order); (2) a component whose files, and whose path dependencies' files, are unchanged since the last passing gate (a stamp recording the tree hash per component) skips its fmt, clippy and test, and the stamp is invalidated by any change it depends on; (3) time each stage and print the slowest ones. The gate's result must stay identical: a failure anywhere still fails it, and just gate --full ignores the stamps. Measure before and after on a merge-sized change and record the numbers in docs/speed.md.
